- **F1 current browser verification, 2026-11-13:** In Chrome 157 on the local fictional preview, unknown → accepted-selector → same-intent retry and unknown → rejected-selector → same-intent retry both displayed the unresolved warning and preserved the original appointment display. The same intent remained blocked after a tab reload and after switching records and exercising other examples. A fresh rejected example preserved its original appointment; a fresh accepted example displayed the simulated accepted result. A separate rejected cancellation remained available, and using it did not clear the unresolved reschedule marker. These observations verify the illustrated paths only.
- **F1 limits:** The correlation and tab-session storage are demo-only. Closing the tab, clearing session storage, using another tab, or storage being unavailable can lose or isolate the marker; the in-memory fallback survives only until reload. No authoritative result or reconciliation was implemented. Whether a changed destination or another action is safe while a real outcome is unknown remains an open production design/policy question; this preview does not decide it.
