## FND-Q02 — proposed minimal configuration contract

For Product Owner and engineering/security review, not approved:

1. Require an explicit context selection of `local` or `testing` before initialization. Missing, invalid, ambiguous or production/client context fails closed; no auto-selection, context fallback or mutation. Keep context inputs separately supplied for development and tests and verify no cross-context bleed.
2. Use only configuration needed for framework bootstrap and the selected response. The exact keys, source precedence and whether a local application key is technically required must be determined during authorized compatibility evaluation; no production credentials or business/branding policy values. If a key is required, use a separately generated local-only value, stored outside tracked source and public artifacts.
3. Disable debug output and all database, mail, queue and external integration attempts. No database target or credentials are required. Do not silently replace a missing service with a persistence service. Runtime diagnostics, if enabled, are local and access-restricted, contain only safe categories, and never expose secrets or internal paths in public output; exact destination and access need security review.
4. Validate synthetic missing, malformed, mixed and conflicting inputs with controlled interception. Never probe CEAP or a real client. C02–C06 and C08 apply. This verifies configuration behavior, not real client isolation.
